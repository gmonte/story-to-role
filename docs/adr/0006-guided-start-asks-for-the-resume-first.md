# The guided start asks for the resume before the opening

The workspace spec lists the "I have an opening in mind" path as: paste the opening, upload the current resume (or a truth file, or say there is none), see the fit check, answer a short interview about what the opening needs, get the resume. The fit check reads only approved positions and evidence, and runs once, when the opening is analyzed; nothing reruns it when the evidence grows. Asked for in the spec's order, the first fit check would always judge an empty career and show every requirement as a gap, which is the opposite of "the first proof of value". So the guided path asks for the resume first and lets the opening in only once the import has finished and its positions are approved, or once the user says they have no resume (then it offers the short "what do you want to work with" interview before the opening, or the opening anyway, its gap questions filling what is missing).

## Consequences

- The path's steps are the spec's, in a different order; the outcome (fit check, gap questions, resume) is unchanged and happens on the opening's page.
- If the fit check later learns to rerun when evidence changes, the spec's order works again and this decision can be revisited.
